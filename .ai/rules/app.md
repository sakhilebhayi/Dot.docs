# App

## All document content writes go through DocumentStore
Never write Document::content, content_json, search_text, word_count, or version directly (e.g. via ->update([...]) or ->save() after mutating those fields by hand). Always go through App\Documents\DocumentStore: create() for new documents, save() for edits (accepts Dot.Doc JSON, validates against DocumentSchema, renders HTML, updates search_text/word_count, and cuts a version per the auto/named/restore/none rule), restore() for version restores, and refill() only from the one-off backfill command. Any writer that produces HTML (importers, AI suggestion acceptance, legacy content) must first convert it with App\Documents\Import\HtmlToJson::convert() and hand the resulting JSON to DocumentStore::save(). This keeps content, content_json, search_text, word_count, and version snapshots from drifting out of sync. Found drifting in DocumentImportController::store() and Editor::acceptSuggestion() during Task 4 review (fix round 1).

## DocumentSchema::normalise() repairs what ProseMirror's content expressions reject
`DocumentSchema::validate()` and ProseMirror's content expressions are NOT the same check. validate() is happy with an empty `<table>`, a `bulletList` with no items, a `listItem` that opens with a nested list, or a `columns` whose child count does not equal `attrs.count`; ProseMirror refuses all of them - and the editor is built with `enableContentCheck: true`, so ONE of them opens the whole document READ-ONLY with autosave off. `normalise()` therefore repairs as well as whitelists: it drops empty `table`/`tableRow`/`bulletList`/`orderedList`/`taskList`, gives an empty `listItem`/`taskItem`/`tableCell`/`tableHeader`/`blockquote`/`callout`/`column` (and an empty `doc`) a paragraph, prepends a paragraph to a `listItem`/`taskItem` that does not start with one, makes `columns` children match `count` (extras MERGE into the last column, never dropped; short ones are padded), and forces `figure` to `(image|table) caption` WITHOUT LOSING ANYTHING: the first media child and the first caption stay inside, and every other child is LIFTED OUT as a sibling immediately after the figure. A lifted child becomes a paragraph unless it is itself top-level-valid: `liftToBlock()` passes through anything already legal as a direct child of `doc`/`column` (both are `block+`) unchanged - `image`, a second `figure`, and so on - and converts everything else (`column`, `tableRow`, `tableCell`, `tableHeader`, `listItem`, `taskItem`, `caption` - content ProseMirror only allows inside one specific parent) into a paragraph of its own plain text (`DocumentSchema::plainText()`), keeping its own block id, dropped only when that text is empty. `enableContentCheck` would otherwise refuse a `column` or `tableRow` sitting bare at `doc`'s top level exactly as it refuses a stray `caption`. The same rule applies everywhere normalise() moves a node to a new parent, not just out of a figure - `normaliseColumns()` runs a `columns`-child that is not itself a `column` through `liftToBlock()` too before wrapping it into a synthetic column, since `column` is `block+` just like `doc`. A figure with no media at all cannot be a figure, so it is replaced by what it was holding rather than deleted with it. Keeping only the first two children silently deleted the writer's second picture. This is why `normaliseNode()` returns a LIST of nodes, not one node - a repair may expand into several - and why `normaliseChildren()` splices rather than appends. Nodes normalise() creates from nothing (an empty paragraph, a padded column) carry a fresh `BlockId::generate()`, because `validate()` runs after it; nodes `liftToBlock()` converts keep the id they already had, because `ensureIds()` (which runs before `normalise()` on every write path) already made it valid and document-unique. It is run by `DocumentStore::create()`/`save()` on the way in, by `HtmlToJson::convert()` (every legacy blob, importer and AI acceptance) and by `DocumentStore::json()` on the way OUT to the editor, which is what makes a document stored before these repairs existed still open editable. Guard `count($node['content'] ?? [])` against non-array content throughout: this data comes from importers and from the wire. The same goes for `attrs`: a block whose `attrs` arrived as a non-array scalar (e.g. a malformed autosave payload) must be treated as `[]` in both `ensureNodeIds()` and `normaliseNode()` - unguarded, `array_merge()`/`array_key_exists()` throw a TypeError (a 500) instead of leaving the input to fail `validate()` normally.

## The editor's beacon autosave is a controller, and it still writes through DocumentStore
`App\Http\Controllers\DocumentAutosaveController` (`POST /documents/{uuid}/autosave`, inside the `auth:sanctum` group) exists because Livewire cannot issue a request during page unload - its CommitBus defers every `$wire` call on a 5 ms timer the unloading page never runs - so the editor's last-chance flush uses `navigator.sendBeacon()`, which can only POST to a plain endpoint. It is not an exception to the "all content writes go through DocumentStore" rule above: it authorises `update`, validates that the body is a `doc`, calls `DocumentStore::save($doc, $json, $user, ['version' => 'none'])` so no version snapshot is cut for someone merely navigating away, translates the store's `InvalidArgumentException` into a 422 `ValidationException`, and returns `{version}`. It saves `$request->input('content')` - the RAW array - never `$request->validate()`'s return value: validate() gives back only the keys it was given rules for, so validating `content.type`/`content.content` and saving that stripped `content.attrs` (schema/style/vars) off every beacon save and let `ensureIds()` re-stamp the defaults, resetting the document's style and variables behind the writer's back. Rules on a nested document body are a SHAPE check only; `DocumentSchema::validate()` inside `DocumentStore::save()` is what vets the content. Anything else that needs to write content from a plain HTTP request follows the same shape.
