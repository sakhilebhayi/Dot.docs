# Livewire

## Full-page Livewire views: exactly one root element, page-level <style> goes inside it
A full-page Livewire component's Blade view must render exactly ONE top-level element. Livewire scans the compiled HTML for the FIRST element and attaches wire:id/wire:snapshot/wire:effects to it as the component root; if a page-level <style> tag (or any other element) precedes the real root <div>, Livewire hydrates the wrong element and the component loses interactivity (wire:click/wire:model bindings inside the intended root never bind). Found in Task 6 review round 1: resources/views/livewire/documents/editor.blade.php had <style id="doc-style">{!! $styleCss !!}</style> BEFORE the root <div x-data=...>. Fix: put the <style> block as the FIRST CHILD inside the root <div>, never a sibling before it. Livewire docs (quickstart, 3.x): "components must have just ONE single element as its root. If multiple root elements are detected, an exception is thrown." Regression test pattern: GET the full-page route and confirm the component's own wire:snapshot (identify it by a property unique to that component, since other Livewire components render on the same page with their own snapshots) is attached to a <div>, not a <style> or other non-root tag.

## Every editor-mutating path in the bridge carries the same fail-closed gate
When the content check refuses a document, mount() calls failClosed(): read-only editor, visible banner, handle.autosaves === false. From that moment what the editor is showing is NOT the document, so every path of the editor page that writes into it or reads a draft has to check handle.autosaves === false first. Those paths are decided in resources/js/editor/sync/host.js, and editor.blade.php only hands over to it (see .ai/rules/editor.md): persist(), clearDraftIfSettled(), restoreDraftIfRestorable() (restoreDraft() in the module), the update listener that writes the offline draft (edited() in the module), the sync engine's applyFromSync() (and syncState(), which reports 'closed'), resendIfOwed(), keepMine(), loadTheirs(), putBack(), applySuggestion() (which was missing the gate and let an accepted suggestion mutate a read-only view), and since Phase 2 mergeOrConflict(), beginMerge() (it fetches a document only to write it back, and its 15 s expiry would otherwise raise "Not saved" on a read-only page), putBackLost(), putBackAllLost(), the draft merge (mergeDraft()) and the suggestion merge (mergeSuggestion()). The test "fail-closed: nothing is saved, nothing is applied, no draft is touched, and the engine is told closed" in tests/js/sync.host.test.js pushes every one of them as far as it goes. Only one of those refusals needs words of its own, because only one answers something the writer has just done from outside the editor: applySuggestion() sets aiError (view.aiError in the module), which the status strip shows next to the @error(content) message. The others return without a word; the content-error banner and the top bar's Read only already say that the document is open read-only. discardSetAside() and dismissLost() are deliberately NOT gated: each touches neither the editor nor a draft, it only withdraws an offer (discardSetAside() asking first when the offer is of this tab's own unsaved typing, set aside by Load theirs; dismissLost() always asking, because every entry of the lost row is text a merge established is on the page nowhere. It is async: it writes the lost- park first and empties the row only when that write is known to have stored the list, keeping every entry on the page and saying so when it did not, and a second question then lets the writer drop the text without a copy; on success it stamps the park dismissed, its entries moved to the row's `dismissed` list that later parks carry over, so the text keeps its 7 days and is not offered again). Adding a new path that touches the editor means adding the gate to it - in the module, with a test. A second gate stands beside it since the read only editor (`.ai/rules/editor.md`): `cannotWrite(handle)` is the fail-closed test OR `readOnly(handle)` (the `editable` literal is false, or a save was refused), and the paths above that write use it. A read only page is not fail-closed: it keeps following (applyFromSync(), syncState()), and `handle.autosaves` stays true.

## Alpine re-creates the editor's data object on every render that changes the x-data string
The editor's `x-data` string contains the document's version and its JSON, and `public Document $document` is re-read from the database on every Livewire request, so the string changes on the first render after anybody saves. When Livewire morphs a changed `x-data` onto the root element, Alpine calls `destroy()` on the CURRENT data object, builds a new one and calls its `init()`. Four things follow. (1) On first load `init()` runs twice on the same object (Alpine's own call plus `x-init="init()"`). The first call mounts the editor with `owns` true and sets the page up; the second finds the editor already mounted, sets `owns` to false and returns at `if (!this.owns) return;`. Every later object finds the editor mounted too, so `owns` ends up false on EVERY object, and the last block of `destroy()` (destroy the editor when `owns`) never runs, not even when the element is really removed; the element only ever goes away with the page. Leave `x-init` where it is: the wiring tests anchor on it, and removing it changes which object owns the editor (the first object would keep `owns` true). (2) `destroy()` runs on the old object at each re-init and must not tear down anything that lives on the ELEMENT - the editor handle, the sync engine parked in `__dotdocSync` - so it returns early while `this.$el.isConnected`; only a real removal gets past that line. That guard, not `owns`, is what keeps the editor and the engine alive across a save: without it the engine is stopped on the first render after a save and the tab never polls again. (3) Handlers bound at first load (`persist()`, the engine's host callbacks, the window listeners, the notice bar's buttons) stay on the FIRST object; each later object only runs `init()` as far as `if (!this.owns) return;`. Anything `init()` does before that line therefore runs again on every re-render, which is why the outline is seeded from `data-outline` only when `this.owns`: that attribute sits on a `wire:ignore` element and still holds the page-load outline. The tab id is made before that line too (`createTabId()`, once per object), so every later object gets a new one, and only the first object's is ever sent: the engine and the `pagehide` beacon were set up from it. It is also why the page's decisions are made by `resources/js/editor/sync/host.js`, built afresh from `this` for every call and holding no state of its own: new decision logic goes there, with a test, never into this attribute (see `.ai/rules/editor.md`). (4) A morph does not only add and remove elements. For EVERY element it patches it first initialises the INCOMING copy (`Alpine.cloneNode(from, to)`) against the root's current data stack - after the first changed `x-data` string that is the NEWEST object, whose `conflict`, `setAside`, `syncNotice`, `aiError` and `unsaved` never change - and then copies the copy's attributes and children onto the live element. `x-show` alone is guarded: `patchAttributes()` leaves the live element alone when the copy's `_x_isShown` differs from its own. `x-text`, `x-bind` (`:disabled`, `:class`, `x-bind:hidden`) and `x-html` are NOT guarded, and rendering the element on every render does not help them: a render while the conflict notice showed (somebody leaving the document is enough) disabled Load theirs until the next poll, and a render while a sync notice showed removed its sentence for good, leaving a red dot and no words. So an Alpine binding other than `x-show` that reads the page's state (an event handler is fine: the copy never runs one) lives under `wire:ignore`, where Livewire skips the element before it clones anything - and whatever is under `wire:ignore` must contain nothing the server renders, because it is never brought up to date. That is the notice bar (next section) and the strip's `aiError` word. What has to stay server-rendered uses `x-show`, on an element that is rendered the same on every render: an element Livewire ADDS on a later render (a conditional branch that comes back, such as the Saved / Ready word after a rejected save) is initialised then and bound to the newest object for good, which is why that word's `x-show` sits on a wrapper span outside the conditional and not on the word. Known and not fixed (it is older than this rule): the Pages button's `x-bind:aria-pressed` reads `thumbnailsOpen` and is exposed to the same morph.

## Notices with actions live in the notice bar, never in the status strip
The status strip (`.doc-status`, in the editor's bar `.doc-bar`) is ONE line that does not wrap, in a row that does not wrap. It carries a word and a dot: Saved or Ready (rendered by the server), Saving (`wire:loading`), Editing, Offline, Not saved. Two things in it are longer than a word, and they are exceptions, not models: the reason of a rejected save (`Not saved — ` and at most 60 characters of the `content` error, the whole of it in the `title`), and the `aiError` sentence (a refused AI result or suggestion; click to dismiss), which belongs in the notice bar and should move there when it is next touched. Anything the writer has to read in full or answer goes in the notice bar, `.doc-notices`, directly under `.doc-bar` (the two share the wrapper `.doc-head`): the conflict notice with Keep mine and Load theirs, the lost row (Phase 2: what a merge could not keep, five static item slots each with its sentence, its excerpt and a Put it back of its own, an overflow line, Put them all back and Dismiss all; `x-bind:hidden="!lost.length"` and `"!lost[i]"`; never `x-for`, so PHPUnit pins every element and no Alpine pattern new to the bar is introduced; the list is `max-height: 40vh` and scrolls inside the row, so the sticky head cannot outgrow a phone's viewport and put Put them all back and Dismiss all out of reach), the set-aside notice with Put it back and Discard, and the sync notice. They used to sit in the strip, and there the buttons were measured outside a 751px window and underneath the dock at 1440px: the writer was told to choose and could not. While the conflict notice shows, the strip's word for it is Not saved and the sentence is in the bar; Editing or Saving can stand beside that word while the writer types or a Keep mine save is in the air.

The strip never says Saved over text that is not stored. The Saved / Ready word is whatever the server last rendered, so its wrapper is shown only while `!isTyping && !isOffline && !conflict && !syncNotice && !unsaved`. `unsaved` is the page's own knowledge that the editor holds text no accepted save has stored (`.ai/rules/editor.md`); without it the word came back as Saved after a save that failed or never answered, while the top bar said Saving or Not saved. The strip can therefore show no word at all for a moment (between the end of typing and the autosave, or while a failed save waits to be sent again); the top bar keeps its own word throughout. Do not fill that gap with a word driven by `unsaved` alone: `unsaved` stays true until the save answers, so Editing would stand beside Saving during every save.

What keeps the bar reachable, all in `resources/css/shell.css` (`.doc-head`, `.doc-notice*`): it is in normal flow inside the editor column, so it never extends under the rail or the dock column; nothing in it has a fixed width, the sentence wraps and the buttons drop to a line of their own when they do not fit beside it; `.doc-head` is the sticky element, so where the page scrolls (below 900px) the notice stays on screen with the bar; between 900px and 1180px, where the dock is a sheet over the right of the canvas, the rows keep clear of it (a `:has()` on the open dock, because the dock comes after the canvas in `.shell`); and the floating toolbar's ceiling in `resources/js/editor/ui/bubble.js` includes `.doc-notices`, so a selection in the first line does not put the toolbar over the buttons. The bar is a live region (`role="status"`), its buttons are real `<button type="button">` elements in reading order, and its look is the frame's own: `--surface`, a 1px `--line` rule under each row, the status dot for tone, no card, no shadow, no coloured stripe. Its surface and inks are rows in `scripts/design/contrast-dom.mjs`. What each button does to somebody's text is in its `title` AND in a hidden element in the same row that the button is described by (`aria-describedby`), saying the same sentence: a `title` is not shown to a keyboard and screen readers treat it unevenly. A button pressed from the keyboard hands the focus back to the document without scrolling (`noticePressed()` in the page's component, called by ONE `@click` on the bar after the button's own handler; a click the browser made from Enter or Space has `detail` 0), because the row that held the button goes away once the choice is carried out and the focus was left on nothing. It does not do that after a mouse click or a tap, where it would bring up the on-screen keyboard.

The bar is `wire:ignore`, and its rows are switched with the `hidden` attribute, not with `x-show`. Both follow from the Alpine rule above. `wire:ignore`: every morph would otherwise evaluate the bar's bindings on the incoming copy against the newest data object and write the outcome onto the live rows (with `x-bind:hidden` and no `wire:ignore`, the next render hides every notice; both were run against the installed Livewire bundle under a DOM emulation). The price is that NOTHING in the bar may be rendered by the server: no Blade condition, no echoed value, no `wire:` directive but that one. It is static markup that Alpine shows, hides and fills. `hidden`, not `x-show`: after its first evaluation `x-show` applies a change only inside `requestAnimationFrame` while the page reports itself visible, so in a tab that is not being painted a notice stayed on screen after its state had gone, and one that should appear would not have; `x-bind:hidden` writes the attribute in Alpine's own flush and waits for no frame. Each row (and each of the two sentences of the set-aside row) carries `hidden` in the markup, so nothing shows before Alpine runs and no `x-cloak` is needed, and `shell.css` has `.doc-notice[hidden], .doc-notice [hidden] { display: none; }`: `.doc-notice` is `display: flex`, which beats the browser's own rule for `[hidden]`, so without that rule every notice shows all the time. Never use `x-bind:hidden` on an element outside `wire:ignore`. The Saved / Ready wrapper in the strip is the opposite case and must stay on `x-show`: what it wraps is server-rendered, so it cannot be ignored by the morph, and in an unpainted tab its change waits for the next frame.

The set-aside row says what it is, per source (`setAsideFrom`, set by `sync/host.js`). After Load theirs (`'conflict'`): "Your text was set aside. Put it back replaces what is on the page now; the version it replaces is kept in the history." For a draft found at page load that the document has moved past (anything else): "A draft from your last visit here differs from the document as it is now. It may already be part of it." The page took nothing away in that case and cannot tell text that was never stored from text the unload beacon stored and others then built on, so it must not say Your text was set aside there; Put it back then asks before it replaces anything (`putBack()`, `.ai/rules/editor.md`). Discard only withdraws the offer, and asks first when the text is this tab's own unsaved typing (set aside by Load theirs), because that text is in no saved version; the button's `title` says so. The conflict sentence does not say Do not reload: a reload sets the tab's text aside as such a draft and offers it back - but only when no second tab of the same browser is open on the document, because the draft is keyed per document, not per tab, and that tab clears it when it follows the save (a browser that cannot keep a draft loses it too).

`EditorSyncWiringTest` pins where the bar is, that it is `wire:ignore` and its source holds nothing the server renders, the `hidden` attribute and the four row bindings (`!conflict`, `!lost.length`, `!setAside`, `!syncNotice`), the CSS rule, the sentences (the conflict sentence says the two could not be combined), the eleven buttons with their titles and descriptions (Keep mine, Load theirs, five Put it back, Put them all back, Dismiss all, Put it back, Discard), the lost row's five slots and overflow line (the six buttons that read Put it back differ by their description: each lost-row one lists the ids of its own item's `doc-notice-lost-N-count` (a `.sr-only` Item N of M, because two items can share their first 80 characters: both versions of one paragraph), `-sentence` and `-excerpt` before the shared what-it-does id, and the sentence is `.doc-notice-sentence`, an ink in the contrast gate), the one click listener, that the strip holds no button, the `aiError` word's `wire:ignore`, the Saved wrapper's condition, the eight merge state fields (`overwriteFloor` among them) and the three lost-row delegates, and that the page hands over to `sync/host.js` (`createSyncHost(this`, `this.syncHost().engineHost()`, `getOverwrite`).

## The editor's x-data object is ONE double-quoted HTML attribute: no double quote inside it
A double-quote character anywhere inside the `x-data="{ ... }"` component, a comment included, ends the attribute at that point: the component is cut off, the rest becomes stray attributes, `x-init` is lost and the editor never mounts, while the server renders the page without complaint. Use single quotes, and in comments write the words without quotation marks. `ContextualToolbarTest::test_the_editors_alpine_component_survives_being_an_html_attribute` and `EditorSyncWiringTest` read the attribute the way a browser does and fail when it is cut short.

## `editable`, `unsentKept` and `accessCheckSince` are the page's read only state, and `editable` is the one server literal that may change a gate
`editable: {{ $canEdit ? 'true' : 'false' }},` in the x-data object is a plain boolean from `Editor::render()` (`canEdit`, `.ai/rules/app.md`), drawn on every render like `documentVersion`. It follows the quoting rule above (nothing with a double quote in it) and the no-logic rule (`sync/host.js` decides by it; the attribute only holds it and hands it to `mount({editable: this.editable})`). It is ALSO written by the host: a refused save, once `Editor::canEdit()` has said no, sets it false on the object that owns the editor, because the notice bar reads that object. When the server then draws `editable: false` into a new string, a later Alpine object holds it too, but the host reads the editor handle (`handle.readOnly`, which lives on the element) as well, so a re-created object cannot make the page editable again. The controls the server draws for a writer (title, style picker, Move, the More menu's writing items, Accept/Drop) are `@if ($canEdit)` / `@readonly` / `@disabled`, not Alpine bindings: they follow on the re-render the refusal asks for, and an `x-bind` outside `wire:ignore` would be exposed to the morph rule above. The strip's `Read only` word sits inside the same x-show wrapper the Saved / Ready word does (rendered the same on every render). The notice bar's read only row is hidden while a stop reason shows (`editable || !!syncNotice`), because the stop reason says more.
