# Print

## PageSetup merge order and dompdf page_text mechanism
PageSetup::fromDocument(Document, DocumentStyle) merges $doc->page_setup (per-document override, set via DocumentSettings::savePageSetup()) OVER $style->tokens['page'] (DocumentStyleSeeder) via array_merge, so an explicit document value always wins; unknown size (not A4|A3|Letter) or orientation (not portrait|landscape) fall back to the class defaults (A4/portrait) rather than reaching the @page rule unvalidated, and margins go through App\Styles\TokenGuard::length() the same way CssBuilder does. Page numbers ({{ page }}/{{ pages }} in header/footer templates) cannot be resolved at HTML-build time - dompdf only knows a page number while it paginates the PDF - so PrintRenderer::html() leaves them for dompdf: any header/footer template containing them renders an EMPTY DOM band (PrintRenderer::band() returns html=''), and the real text (with {{ page }}/{{ pages }} rewritten to dompdf's own {PAGE_NUM}/{PAGE_COUNT} placeholders) is instead drawn onto every page's canvas by a <script type="text/php"> block calling Canvas::page_text($x,$y,$text,$font,$size) - dompdf's documented page-numbering convention (vendor/dompdf/dompdf/src/Adapter/CPDF.php::page_text(), which internally str_replaces {PAGE_NUM}/{PAGE_COUNT} in $text once per page via processPageScript). This requires Options::isPhpEnabled (set via Pdf::setOption(['isPhpEnabled'=>true]) on the Barryvdh\DomPDF\Facade\Pdf instance in PrintRenderer::pdf()), or dompdf silently ignores the script tag (PhpEvaluator::evaluate() no-ops when !getIsPhpEnabled()). Because header/footer text is user-editable (DocumentSettings::savePageSetup(), validated only as nullable|string|max:200 - no content restriction), PrintRenderer::phpStringLiteral() escapes it as a safe single-quoted PHP literal (addcslashes for backslash and single-quote) and neutralises literal '</script' before it is embedded in the eval'd <script type="text/php"> block - otherwise a crafted footer template is a PHP eval() code-injection / extra-script-tag-injection vector at PDF-render time, not just an HTML-escaping concern.
