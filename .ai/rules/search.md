# Search

## Search access predicate is DocumentPolicy::view(), narrowed to the current team
SEARCH (App\Search\DocumentSearch) has ONE access predicate for both drivers: owner OR named collaborator OR CURRENT team OR is_public. That is DocumentPolicy::view() as SQL with one deliberate narrowing - the policy admits any team the user belongs to (`belongsToTeam`), search is scoped to `currentTeam`, as the brief specifies - so a multi-team user will not find a document in one of their OTHER teams until they switch to it. Do not describe the two as an exact mirror; the gap is real and it runs in the safe direction. A search that returns a row the policy would refuse is a disclosure, so the predicate may be narrowed but never widened past the policy; widening it to `belongsToTeam` is a product decision, not a bug fix. pgsql matches documents.search_vector (the generated tsvector over title + search_text) ranked by ts_rank; sqlite (production and tests) goes through App\Search\TextMatch, shared with the header search (CompanyDocuments): the title matches any part of a word (escaped LIKE), the body is looked up in the FTS5 table `documents_fts` (App\Search\FullTextIndex, R2-5): every word a quoted prefix, all required, ranked by bm25 with the title weighted 10x. The index is external-content over documents(title, search_text), kept in step by three triggers (documents_fts_ai/_ad/_au; the update trigger fires only on a change of title or search_text). A migration that rebuilds the `documents` table drops those triggers: the index is then unused (LIKE fallback) until `php artisan search:rebuild` - and FullTextSearchTest fails, so re-run FullTextIndex::install() at the end of any such migration. Both read search_text, which DocumentStore::fill() rewrites on every save - never search `content`, the rendered HTML, except through the narrow legacy clause (search_text IS NULL) that keeps documents not yet processed by `documents:migrate-to-json` findable. Queries shorter than two characters are not searches at all. Cost of the update trigger, measured 2026-11-27 (docs/programme/EA9_MEASUREMENT.md section 5): about 0.2 ms p50 per save of a 25 KB document, under 2 ms p95 - kept as a trigger; Eloquent only SETs search_text when it changed, so a formatting-only save never re-indexes.
